## 1. 文档定位

本文用于交接 **2026 全国大学生嵌入式芯片与系统设计竞赛 FPGA 创新赛道——中科亿海微选题二：PMUX 结构优化** 当前已经完成的验证基础设施、工作环境、评测方法、Git 工作流和后续开发约束。

当前阶段的核心成果不是 PMUX 优化算法本身，而是已经建立并验证了一套能够长期复用的：

> **原版 Yosys baseline + 优化版 Yosys optimized + 同一 Tcl 脚本 + Cyclone IV 映射 + EQY 等价验证 + 资源/时间/内存统计 + 可复现 manifest**

统一评测框架。

这套框架已经经过 identity test 和 negative test 验证，可以作为后续所有 PMUX 优化工作的固定基线。

## 2. 项目目标与官方评测理解

当前任务目标是优化 Yosys 中的 `$pmux` 结构，使综合后的 FPGA 资源占用下降，同时保持逻辑功能严格等价。

当前采用的评测流程为：

1. 在 Yosys 中加入 `pmux_opt` 优化 pass，并重新编译生成 optimized Yosys；
2. 使用 optimized Yosys + 固定脚本处理官方测试用例，生成优化后网表；
3. 使用原版 Yosys + **同一套脚本**处理同样的测试用例，生成 baseline 网表；
4. 使用 EQY 比较原始 RTL 与 optimized Yosys 生成的 generic netlist；
5. 对 baseline 与 optimized 的 FPGA 映射结果统计总 cell、Cyclone IV combinational logic cell、DFF；
6. 同时比较运行时间和峰值内存；
7. 所有比较采用相对变化量。

固定目标器件映射为：

```text
Cyclone IV
```

当前 Yosys 命令：

```text
synth_intel -family cycloneiv
```

```text

```

```text

```

时间 overhead：

```text
(optimized - baseline) / baseline × 100%
```

### 内存

使用：

```text
Maximum resident set size
```

三个结果取：

```text
max
```

RSS overhead：

```text
(optimized - baseline) / baseline × 100%
```

当前测试用例运行时间很短，所以 0.01 s 的计时粒度就可能产生明显百分比变化。identity 阶段中的小幅 time/RSS 正负波动不能解释为算法效果。

## 18. Identity Test 的意义

Identity test 的目的不是证明优化有效，而是证明：

> 当 baseline 和 optimized 完全相同时，整个评测系统必须得到相同的逻辑和资源结果。

当前已经证明：

```text
4/4 synthesis success
4/4 EQY PASS
4/4 resource exact match
negative EQY 正确失败
一键统计成功
manifest 成功
clean worktree 成功
```

因此后续如果 optimized 与 baseline 出现资源差异，可以认为差异来自真正接入的 PMUX 优化，而不是评测框架不一致。
