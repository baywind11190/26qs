# 2026-10-29 稳定性增量：优先级链查重

## 当前结论

基于59f8bf8的增量，只把优先级链分析中的两处向量遍历查重改为Yosys的pool集合插入查重。优化策略、改写顺序、三个调用位置和搜索预算均未改变；没有修改其他pass、ABC或外部综合流程。

本轮预先固定五批完整综合，按答疑C132触发复核后的45个逐例时间、45个逐例主进程峰值内存结果全部<=5%。这是本轮Linux证据，不能保证任意未来运行均过线，也不能替代Windows正式PeakWorkingSet验收；此前59f8bf8的+6.068%超标记录继续保留。

## 为什么改

此前30对test2带阶段记录的诊断，候选完整时间均值+4.1973%，优化pass均值约0.349ms，额外耗时也分布在后续清理等阶段。因此没有把全部差额归因于插件自身，也没有修改其他pass抵消开销。

优先级链分析原来每访问一层，就从头扫描visited和selectors向量，长链比较次数呈平方增长。改为pool.insert检查是否首次出现，避免反复扫描；集合仅用于成员判断，不通过遍历集合决定改写顺序。chain仍保持原来的优先级顺序。短用例是否改善，以完整测量为准；本改动不能被描述为单独消除了全部test2波动。
