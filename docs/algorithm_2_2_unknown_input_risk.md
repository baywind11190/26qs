## 安全折叠与误折叠的区别

在 `control == K` 的分支中，可将 control 固定为 K，对数据表达式求值。
例如已知 control=3，则 control+1 可以替换为常量 4。
但分支条件没有确定的输入 p/q 仍可独立变化。
这里“外部输入”指相对于 control==K 的已知条件仍未确定的信号，
不一定仅指模块输入端口，也可能来自其他状态或数据路径。

旧 2.2 使用 `ConstEval(module, State::Sx)`，将未确定信号以 X 求值。
对普通保守传播而言，不能确定的结果保持原信号；
但某些运算会将 X 输入产生的结果解释为确定的 0/1。
例如 case equality `===`：

```verilog
// 此分支只确定 control，并未确定 p 和 q。
data = t & (p === q);
```

若把 p/q 都代为 X，`X === X` 得到 1，求值结果会成为 t。
若分支还确定 t=1，旧规则可能把 data 替换为常量 1。
然而真实输入 p=0、q=1 时，原 data=0，替换后的 data=1。
因此，这个求值结果不能作为“对所有未确定输入都恒定”的证明。
这是功能正确性边界，不能仅通过 LUT 数量下降判断是否安全。

## 千节点压力测试的判断方式

风险是否触发由表达式结构决定，不由 1000 这个数量决定。
扩大已有安全结构不必然触发问题；较小电路也可能包含触发结构。
若统一压力用例含未确定输入的 case equality 等非保守 X 求值结构，
并进入 2.2 的选择条件折叠路径，就可能暴露功能问题。
尚未取得用例时，不能判断其是否含这种结构，也不能估计发生概率。

取得统一用例后，应检查：

1. 实际进入 2.2 的控制条件与数据表达式，是否仍有未确定输入。
2. 原始 RTL 与 ABC9 后 `$lut` 网表的功能等价性。
3. cell 数量、运行时间和内存，按届时统一要求记录。

现阶段保持公开四例的正式验收工作；此项作为已记录边界。
若统一用例触发该问题，再以独立最小修复提交处理，
例如保留符号未知输入、对不安全算子保守跳过，或增加可靠的条件恒定性证明。
这些是后续可选处理方向，本次未实施。
