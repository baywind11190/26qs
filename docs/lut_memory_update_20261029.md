# 2026-10-29 balanced 峰值内存优化：LUT 输入排列归一化

## 问题与范围

队友的Windows报告00_report(5).md验收8760cd0：九例面积平均下降22.020%，18条原版/候选功能证明通过，所有时间在5%内；balanced主Yosys峰值26.441→28.359MiB，+7.254%，是该报告唯一5%阻断项。本轮针对该内存问题继续开发，不能据Linux数据直接宣布Windows已修复。

相对于8760cd0，产品代码只在src/pmux_opt.cc中新增normalize_lut_input_permutations，并在既有pmux_opt -lut结束时调用。没有新增pass、改变原有调用顺序、修改其他pass/ABC/映射器、操作系统内存策略或测量时扣除开销。

## 定位和改法

减少临时CellTypes复制、缩短图构建临时表生命周期的两个原型，虽然某个接口压力用例能节省1.14MiB，但实际balanced的15组均值仅改善约92KiB/31KiB，不足以解释或覆盖Windows缺口，因此均未纳入产品源码。类型表原型固定五批仍有一次balanced首次内存+5.3213%；聚合数据保留在lut_memory_20261029/discarded_type_registry_experiment.json。

阶段诊断提示较高峰值出现在后续厂商映射。balanced的LUT数从426降到381，但不同(width,truth-table)模板由原版118种增加到候选140种，造成额外模板实例化开销。输入排列归一化把候选模板降到92种，实际完整综合峰值随之下降。

新函数对每个选中、非keep、1～4输入且真值表完全确定的LUT，枚举最多24种输入排列，选择数值最小的等价真值表，并同步排列A口：新输入第j位取旧输入order[j]，新表address项取旧表在original[order[j]]=address[j]处的值。输出Y不变，不增删LUT或NOT，也不使用不可达输入假设。

按(width,truth)缓存计算结果。keep模块/单元、keep或init输出线及别名受保护；无LUT时跳过分析。常量输入和重复输入也保持同一逐项真值表函数。该处理属于已有映射后LUT模式，适用范围与该模式一致，不根据用例名或信号名启用。

## 验证

- 新回归穷尽全部256个三输入真值表，并加入64个随机四输入表；检查归一化目标、320个函数整体SAT miter等价，以及重复执行幂等。旧版有238个非归一化表，RED；新版GREEN。
- 九例原始RTL到ABC后网表真实归纳全部PASS，故意取反寄存器D的负对照得到反例。
- 九例逻辑与DFF与8760cd0完全相同，面积均值22.02025221001536%。
- 局部LUT随机/1000节点/keep/共享输出/局部选择/非法输入/黑盒端口共38项边界通过。共享输出检查保留“不删cell且Y不变”并作完整输出Formal；局部选择检查未选cell完全不变并作Formal。输入排列允许变化，因此不再把所选cell参数逐字不变作为这两项的要求。
- 独立只读代码审查未发现确定问题，覆盖排列方向、宽度、常量/未知、keep/init、选择范围与缓存生命周期；审查未运行测试，也未污染测量。
