# 2026-10-30：前端译码 PMUX 选择顺序优化

本轮目标：全部九例相对原版逐例逻辑不增加，面积降幅算术平均严格大于20%；每例完整墙钟及主进程峰值内存增幅不超过5%。用户要求完成必要验证即可，不反复择优测量。

## 最终产品改动

仅改 src/pmux_opt.cc 中现有 8.1 译码 PMUX 重构的选择位顺序：原来固定低位在根，现在对已经通过原有安全检查的2~3位译码控制，最多评估6种位顺序。对每个输出位构建仅用于计分的共享mux节点ID，选择节点数最少的顺序；相同成本保留原低位顺序。最后只生成一棵原生 $mux 树，继续经过完全相同的原有 Yosys/ABC9 流程。

评估不生成候选网表、不调用综合、不访问映射后 $lut；每种顺序递归深度最多3，数据表最多8项。工作量随输出位宽线性增长，最多6种顺序。评分是共享单比特mux DAG的成本代理，实际生成向量mux树，因此不能单凭评分保证最终映射面积，仍以九例实测判断。

本轮没有修改 -arith 算法、ABC或其他原有pass，没有增加调用阶段，没有调整原有pass顺序，没有改测试RTL。后端 -lut 仍已删除且调用会报错。本方法直接重构已有 PMUX，不能将此说明表述为官方已逐项批准算法。

辅助修改：run_final_nine_regression.py 的面积门槛由旧21%改为本轮20%；新增选择顺序回归和Linux性能采集工具。后者只用于测量，不是产品综合依赖。
