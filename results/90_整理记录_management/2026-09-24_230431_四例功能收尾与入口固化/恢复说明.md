# 恢复说明（不依赖 git reset/checkout）

本记录保存了入口改造前所有将修改文件的副本与当时未提交改动补丁。恢复方法：

## 一、恢复入口文件

```bash
M="results/90_整理记录_management/2026-09-24_230431_四例功能收尾与入口固化"
# 顶层文件
cp "$M/backup/scripts_pmux_validation/"{validate.py,report.py,test_validation.py,PACKAGE_SHA256.json,config.json,POLICY.md,SKILL.md} scripts/pmux_validation/
# runner（可用全量副本覆盖；被修改的 4 个文件亦在 runner_full 内）
cp -r "$M/backup/scripts_pmux_validation/runner_full/." scripts/pmux_validation/runner/
# 套件（manifest 与自检素材）
cp -r "$M/backup/scripts_pmux_validation/suite-official4_full/." scripts/pmux_validation/suite-official4/
```

说明：全量副本 `runner_full/` 与 `suite-official4_full/` 恢复后会把本轮新增文件一并还原为“不存在”状态需
逐个删除（新增：`runner/function_common.py`、`runner/precheck_supported_config.py`、`runner/miter/`、
`suite-official4/selfcheck/{checks.json,mapped_model_gold.v,mapped_model_gate.v}`）——如只恢复被修改文件，
用 `backup/scripts_pmux_validation/` 下同名文件逐个 `cp` 覆盖即可，不必删除新增文件（新增文件不被旧代码引用）。

## 二、恢复 WSL 已安装技能

```bash
cp "$M/backup/skill/SKILL.md" /home/fpga/.agents/skills/pmux-stable-validation/SKILL.md
```

（不改 Windows/Codex 侧技能；该侧本轮未触达。）

## 三、未提交改动

- 修改前工作区已有的未提交改动已随备份副本完整保留；差异见 `backup/git_uncommitted/uncommitted.diff`。
- **恢复时不得执行 `git reset/checkout/clean`**（会破坏未提交改动与实验结果）。

## 四、自检缓存失效与恢复

- 共享缓存：`results/官方口径评测/_共享自检缓存_selfcheck/selfcheck_cache.json`（备份于本记录 `backup/`）。
- 本轮模型/策略版本进入指纹：旧缓存条目自动失效（无需手工删除）；如需强制重跑自检：

```bash
rm -f "results/官方口径评测/_共享自检缓存_selfcheck/selfcheck_cache.json"
```

- 恢复旧入口（p1）后，由于指纹包含 flow_version/model_version/strategy_version 与包文件哈希，
  旧缓存不会与 p1 混用；如指纹不符将自动重跑自检。

## 五、验证恢复完整性

```bash
sha256sum -c "$M/backup/backup_manifest.txt"   # 逐个校验备份副本（路径以备份根为准）
```

备份清单覆盖：顶层 7 文件、runner 4 个被改文件、suite manifest；另含全量 runner/套件副本（自校验哈希未逐条列出，可用 `diff -r` 对照）。
