# 共享自检缓存首运缺陷修复说明（2026-09-24）

本次为 `pmux-stable-validation` 入口（official4-p1）的**最小缺陷修复 + 补测**，并完成
审计清单预存漂移的**核清与同步**。目标是让四例插件预检能够在首次运行环境（共享自检
缓存目录尚不存在）正常执行。**未修改算法、未做内置集成、未重跑内置阻断**；
第 01/02 轮记录原样保留。

## 1. 背景与根因

- 触发场景：对提交 `5c44e87ec403a4e2d7f961e09a3cae6f09919074` 执行插件预检
  （第 02 轮）时，`flowcheck` 通过后中断：
  `ERROR: [Errno 2] No such file or directory:
  '.../results/官方口径评测/_共享自检缓存_selfcheck/selfcheck_cache.json'`，
  结果 NEEDS_REVIEW（退出码 2）。第 02 轮失败证据保留，未覆盖。
- 根因：`validate.py` 的 `update_selfcheck_cache()` 经 `save()` 直接写共享缓存
  文件，但从不创建其父目录（`_共享自检缓存_selfcheck/`）；该目录在首次运行时
  不存在，且 `results/` 为 gitignore 内容，任何全新环境必然触发。
- 测试盲区：原 17 项单测中 `test_cache_roundtrip` 使用已存在的临时目录，未覆盖
  “父目录缺失”场景，因此模拟测试全通过而真实首跑失败。

## 2. 修复与补测

- `validate.py`：`update_selfcheck_cache()` 写入前创建父目录
  （`path = Path(path)`；`path.parent.mkdir(parents=True, exist_ok=True)`），
  共 1 处小改；语义不变，仅补足“首次运行”能力。
- `test_validation.py`：新增 `test_cache_creates_missing_parent_directory`
  （23 行内），覆盖“缓存目录缺失 → 写入 → 可复用”全链。
- 验证（见 `复现_修复前缺陷与修复后自检.log`）：
  - 修复前：备份版 `validate.py` 确定性复现 `FileNotFoundError`；加入新用例后
    套件为 `Ran 18 tests ... FAILED (errors=1)`（红态，仅新用例失败）。
  - 修复后：`python3 test_validation.py` → `Ran 18 tests ... OK`（绿态）；
    `python3 -m py_compile` 通过。
- 生产验证：修复后重跑插件预检（第 03 轮）全阶段完成，
  `_共享自检缓存_selfcheck/selfcheck_cache.json` 正常生成（7220B，含
  flowcheck / formal_selfcheck / measurement_selfcheck 三项指纹条目）。
