# 清除路径（clrn）最小复现与判据（证据与结论）

- 日期：2026-09-24（初值建模修正轮·补充证据）
- 固定算法提交：`5c44e87ec403a4e2d7f961e09a3cae6f09919074`（本文件编写期间未做任何算法/网表/主入口修改）
- 范围：最小电路复现 + 器件文档/映射规则/模型实现三方核对；不重跑四例、不重跑性能、不提交。

## 1. 问题

映射网表中 dffeas 的实际端口模式为 `(.clrn(R), .prn(1'b1), .ena(E), .sclr(1'b0), .aload(1'b0), .sload(1'b0), .asdata(1'b0))`（ff_map.v 原文见 §3）。第 03 轮中，相关分区在“跨越 reset 边界”时刻出现反例。需要回答：

- 清除（reset→0）语义在器件上由哪个端口/条件承载？
- 为什么认为“自建模型有问题”，而 Yosys 自带模型使用相同表达式？

## 2. 器件文档（Quartus 13.0 官方，本机 /mnt/d/QuartusII_13.0）

1) 形式验证库模型 `quartus/eda/fv_lib/verilog/dffeas.v`（Altera 官方 FV 模型，共 77 行）：

```
assign actual_d = (sclr==1'b1) ? 1'b0 : ((sload==1'b1) ? asdata : d);
assign aset_w  = ~prn | (clrn & aload & asdata);
assign arst_w  = ~clrn | (clrn & aload & (~asdata));
dffep lc_ff (q, clk, ena, actual_d, aset_w, arst_w);
```

   ⇒ **clrn 低电平 = 异步清零**；**prn 低电平 = 异步置一**；数据路径为 `sclr?0 : (sload?asdata : d)`，带 ena 使能。
2) 仿真原语 `quartus/eda/sim_lib/altera_primitives.v`（dffeas 自第 246 行起）：

- specify：`(negedge clrn => (q +: 1'b0))`、`(negedge prn => (q +: 1'b1))`；
- 内部 FF 由 `PRIM_GDFF_LOW/HIGH` 实现，**清零输入为 `!clrn_in || !devpor_in || !devclrn_in`，置位输入为 `!prn_in`**；
- 其局部信号 `reset = devpor_in && devclrn_in && clrn_in && prn_in && ena_in;` 只用于 specify 时序检查与 `nosloadsclr`/`sloaddata` 门控——**它不是“清零执行条件”**。

   ⇒ 官方两处来源一致：**清除 = clrn 有效（低）**，与 sclr/prn 的组合无关。

## 3. Yosys 映射规则（0.69 基线源码）

`techlibs/intel/common/ff_map.v:3-7`（high/low 两分支除 power_up 外连接相同）：

```
dffeas #(.is_wysiwyg("TRUE"), .power_up("high"/"low")) _TECHMAP_REPLACE_ (
   .d(D), .q(Q), .clk(C), .clrn(R), .prn(1'b1), .ena(E),
   .asdata(1'b0), .aload(1'b0), .sclr(1'b0), .sload(1'b0));
```

⇒ 复位/清零语义**完全由 clrn 承载**（R 为映射得到的复位信号）；prn/sclr/aload/sload/asdata 全部绑定为无效状态。

## 4. 模型实现对比（为什么“Yosys 自带同款”不是正确性依据）

本工程 v1/v2 模型与该表达式，与 Yosys 自带 5 个系列（`techlibs/intel/{cycloneiv,cycloneive,cyclone10lp,max10}/cells_sim.v`、`techlibs/intel_alm/cyclonev/cells_sim.v`）的 dffeas 完全相同：

```
assign reset = (prn && sclr && ~clrn && ena);
always @(posedge clk, posedge aload) if (reset) q_tmp <= 0; else q_tmp <= d;
```

- 在映射端口模式（prn=1、sclr=0）下，该条件**恒为 0** ⇒ clrn 从不起作用 ⇒ 模型无法表达网表的清除行为。
- 逐条解释：
  a) 该表达式对应的是官方原语内部**同名门控信号**的“改造版”：官方 `reset` 是 `devpor&&devclrn&&clrn&&prn&&ena` 的合取且**并不执行清零**（只用于 specify/门控）；Yosys 版把它改写为“为真则同步清 0”，语义已偏离，且在端口绑定模式下永远不会为真。
  b) 官方（fv_lib 与 sim_lib，两处独立来源）均把清零/置位语义放在 `!clrn`/`!prn` 上；Yosys 简化模型未反映该语义，且 `power_up` 标为 `"dontcare"`、aload/asdata 未实现——属“简化仿真用、不含清除语义”的模型。
  c) 结论：**相同来源 ≠ 正确语义**。本工程复用该表达式时把缺陷一并引入了形式模型。

## 5. 最小复现（本目录）

- 电路：
  - `mini_clear.v`：gold = RTL 异步复位寄存器（`always @(posedge clk or posedge rst) if (rst) r<=0; else r<=d`）；gate = dffeas 按映射端口模式（`clrn=~rst`，其余同 §3）。
  - `top_clear_norst.v`：rst 恒 0 的对照顶层。
- 配方：与链内策略完全同型（见 `run_clear_check.sh`，复用 `run.ys` 各行：`chformal/async2sync/formalff/setundef/flatten/dffunmap/opt_expr/opt_clean` + `sat -tempinduct -set-init-undef -set-def-formal -set-def-inputs -maxsteps 5 -set-assumes -prove-asserts`）。
- 结果（`run_clear_check.sh` 输出）：

  | 实验 | 模型 | 复位条件 | 结果 |
  | --- | --- | --- | --- |
  | A | v2 | 无（rst=0） | **PASS**（Induction step proven: SUCCESS） |
  | B | v2 | 有 rst 输入 | **FAIL_DETECTED**（Trying induction length 1→2，model found for base case） |
  | C | clrnfix 候选 | 有 rst 输入 | **PASS** |
  | D | clrnfix 候选 | 无 | **PASS** |

- 反例观测（B 日志尾部）：`\ug.r=0`（金侧已清零）而 `\um.u.q_tmp=1`、`\qm=1` 保持 1；`\um.u.reset` 恒 0 ⇒ **门侧从未清零**。
- 因果判定：
  - 分歧与复位事件严格相关（A 无复位 PASS ↔ B 有复位 FAIL）；
  - **仅**把 `!clrn → q_tmp <= 0` 一项补上（`form_cells_cycloneiv_v2_clrnfix.v`，power_up 处理与 v2 保持一致，以隔离单一变量）即消除（B FAIL ↔ C PASS）。
  ⇒ 已证实：“现有形式模型缺清除路径”**足以单独**产生此类跨复位边界反例。

## 6. 结论分级

- 已证实：
  a) 官方语义：clrn 低电平 = 异步清零（fv_lib 模型 + sim_lib 原语，两处一致）；
  b) 现有模型未实现该语义；最小电路上该缺陷单独可产生反例、修复后消除。
- 合理怀疑：
  a) 第 03 轮“跨 reset 边界”反例中的一部分由该缺陷贡献（最小电路已复现同类机制；真实分区未在本轮复验）。
- 未证明：
  a) 补齐清除语义后，四例相关分区（test1 三个 FAIL、test3.rw 等）的真实状态变化——需在口径决定后进行受控重跑；
  b) prn/sclr/aload/asdata 全优先级的一般化实现细节（建议直接对照 fv_lib 模型实现，而非局部补丁）。
