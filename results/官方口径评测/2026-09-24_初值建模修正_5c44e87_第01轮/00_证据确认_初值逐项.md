## 一、逐项确认

### 1. 原始电路规定的初始值（已证实）

| 用例 | RTL 声明 | 依据 |
| --- | --- | --- |
| test1 | `state = START(4'b0000)`、`inter0007 = 1'b1`、`por6 = 1'b0` | `test1.v:67–72` initial 块；`prep` 后 init 属性逐条对应 |
| test2/3/4 | **无任何初始值声明** | 四例全文检索无 `initial`；`prep` 后 init 属性为空 |

已实测 RTL `initial` 经 `prep` 转为 init 属性（`01_证据数据/gold_init_attrs.json`：
`inter0007=1`、`por6=0`、`state=0000`；其余用例为空）。

### 2. 映射网表保留的声明（已证实）

- 每个 `dffeas` 均携带 `power_up`：test1 **222/222 = "low"**（baseline 与 optimized 相同）；
  test3 17/12；test4 10/10；test2 无寄存器。**无 "high"、无缺省**（`01_证据数据/netlist_dffeas_powerup.csv`）。
- 生成机制（`ff_map.v`）：`init === 1 → "high"，否则 → "low"`，同时移除 wire 的 init
  → **"low" 同时覆盖 {声明 0, 未声明(x)} 两类来源**（x 被流程默认化为 low）。这是已证实的细节事实，
  也是下文"待决项"的前提。
- `test1.inter0007`（RTL 初值 1）以**反相存储**实现（`d=state[0]`，`q → $not → inter0007_out`），
  `power_up="low"` 对应输出初值 **=1**，与 RTL 一致（逐位核验）。

### 3. 验证模型与处理步骤中的信息丢失位置（已证实）

1) **模型侧**：v1 的 `dffeas` 未建模 `power_up`（去 initial、参数未用）——门侧初值从未进入证明。
   量化：第 03 轮 test1 的 43 个分区中仅 **3 个**含 init 属性（恰为金侧声明信号
   `state/por6/inter0007`），其余 40 个为 0。
2) **处理侧**：EQY 生成的 `run.ys` 对门侧匹配信号执行 `formalff -clk2ff -ff2anyinit` 与
   `setundef -anyseq`；当门侧 FF 无初值时被释放为自由（第 03 轮 trace：`gate.state=1111` 等）。
3) **修正后量化**：分区 init 属性覆盖 **43/43**（`state`：1+4=5；`por6`/`inter0007`：1+1=2；
   其余由门侧寄存器补全）；且上述两步对**已初始化** FF 为无操作（变体对照：去掉后与标准运行
   逐行一致输出 FAIL/UNKNOWN 结果）。

### 4. 未声明初值寄存器的处理（已证实 + 待决项）

- 金侧：未声明者**保持 x/自由**（`-set-init-undef` 语义：仅未显式 init 置 x，sat.cc 337–343）；
  本轮未引入任何新约束或复位假设。
- 门侧：按网表自带 `power_up` 声明建模（low→0、high→1、其他→自由）。
- **待决项（合理怀疑）**：由于 "low" 含 {0, x} 两类来源，RTL 未声明寄存器（如 test1
  `q*/i*/inter0008/9`）的网表 "low" 可能是流程默认值而非声明 0。v2 当前按"网表声明=器件上电值"
  使用（金侧仍为 x）。是否改为"该情形门侧亦保持自由"（更保守）需口径决策后调整。

## 三、三类归纳（已证实 / 合理怀疑 / 未证明）

**【已证实】**

- 初值声明链：RTL initial → init 属性；网表 power_up（全部 low，含反相实现等价性）；模型 v1 丢失门侧初值；
  修正后注入 43/43。
- 原"基例 1"反例（test1 state/por6_out/inter0007_out）随修正**消失**（基例 1 已通过）。
- `-ff2anyinit/-anyseq` 对已初始化 FF **无操作**（变体对照逐行一致）。
- 错误初值**可被检出**；正确初值对照通过（针对性检查）。
- 网表的 state FF 接线为 `prn=1、sclr=0、clrn=~reset`，而 reset 表达式（厂商 `cells_sim.v` 与本模型
  一致：`prn && sclr && ~clrn && ena`）在该接线下令 reset 恒为 0 → **该配置下模型不执行清除路径**
  （代码级事实）。
- test1 三个新反例均**跨 `reset=1` 边界**出现；trace 显示金侧行为与"带清除"一致、门侧不体现清除
  （现象级事实）。

**【合理怀疑】**

- 门侧"清除路径未建模"是 test1 三分区**基例 2 新反例的主因**（尚未做独立最小复现与修态验证）。
- `test3.rw` 的基例 1 持久失败，疑似为两侧表示差异（金侧为组合 `sr[7]` 且分区将其按输入处理；
  门侧为寄存器输出；无事件时即出现"输入值 ≠ FF 值"）——与初值修正**无直接关联**（未证明）。
- 上文一.4 的 "low 默认化"口径问题（是否应视为器件声明）。

**【未证明】**

- 40 个 UNKNOWN 在"v2 + 更强求解"下能否变化（未在 v2 分区上重跑深度诊断）。
- c4a 与 c4b 分区/状态一致性（本轮与第 03 轮皆相同）所能支持的结论范围——本轮仅陈述一致性事实，
  未作归属推断。
- "清除建模修正"后的四例证明行为（**未实施**，需决策；本报告不预断）。
