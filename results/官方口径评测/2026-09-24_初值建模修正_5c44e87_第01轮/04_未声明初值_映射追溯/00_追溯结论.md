# 未声明初值 → power_up="low" 的映射追溯（证据与结论）

- 日期：2026-09-24（初值建模修正轮·补充证据）
- 固定算法提交：`5c44e87ec403a4e2d7f961e09a3cae6f09919074`（本文件编写期间未做任何算法/网表/主入口修改）
- 范围：只追溯映射来源、说明现有等价检查如何处理“原始未定义初态 vs 映射后确定初态”；不重跑性能、不重跑四例、不提交。

## 1. 追溯链（逐步给出处）

1) RTL 侧（test1.v:46-48）：
   - `state` 声明初值 `4'b0000`、`por6` 声明 `1'b0`、`inter0007` 声明 `1'b1`；其余寄存器（`q0..q7`、`i0..i7` 等）未声明初值。
2) 粗粒度综合后（`05_公开四例_public/round01/test1/optimized/optimized_coarse_done.il`）：
   - 恰有 3 处 init 属性：
     - `attribute \init 4'0000` → `wire \state`（src test1.v:46.5-46.9）
     - `attribute \init 1'0` → `wire \por6`（src 47.5-47.14）
     - `attribute \init 1'1` → `wire \inter0007`（src 48.12-48.21）
   - 其余寄存器无 init 属性 ⇒ “声明/未声明”的区分在映射前存在。
   - 备注：inter0007 的反相已并入寄存器，其聚合初值随后按 0 处理（详见 `00_证据确认_初值逐项.md`）。
3) 映射规则（Yosys 0.69 基线源码）：
   - `techlibs/intel/common/ff_map.v:3-7`：
     - `parameter _TECHMAP_WIREINIT_Q_ = 1'bx;`
     - `generate if (_TECHMAP_WIREINIT_Q_ === 1'b1)` → `dffeas #(.power_up("high")) _TECHMAP_REPLACE_ (.d(D), .q(Q), .clk(C), .clrn(R), .prn(1'b1), .ena(E), .asdata(1'b0), .aload(1'b0), .sclr(1'b0), .sload(1'b0))`
     - `else` → `dffeas #(.power_up("low"))` 同连接
   - `passes/techmap/techmap.cc:637-638`：把 `_TECHMAP_WIREINIT_<port>_` 参数绑定为所连线的 `initvals(...)`。
   - 同文件帮助文本（约 1103-1108 行）原文要点：*“When a parameter with this name exists, it will be set to the initial value of the wire(s) connected to the given port, as specified by the init attribute. **If the attribute doesn't exist, x will be filled for the missing bits.** To remove the init attribute bits used, use the `_TECHMAP_REMOVEINIT_*_` wires.”*
4) 映射结论：
   - 有 init 属性且值为 1 → `power_up="high"`；其它一切（属性值 0 或 **属性缺失 ⇒ 填 x**）→ `power_up="low"`；
   - 映射完成后 init 属性被移除：同名 `mapped.il` 中 init 属性 0 处（对照 coarse 的 3 处）；`netlist_dffeas_powerup.csv` 记录的全部 222 个实例均为 `low`（含声明为 1 的 inter0007——其反相聚合后等价值为 0）。
5) 控制实验（本目录 `mini_init_classes.v`，真实 `synth_intel` 路径；日志 `synth_intel_mini.log`、产物 `mini_init_classes_mapped.il`）：

   | 来源 | 有 init 属性？ | `_TECHMAP_WIREINIT_Q_` | power_up |
   | --- | --- | --- | --- |
   | 未声明（qa） | 无 | `1'bx`（缺省） | low |
   | 声明 0（qb） | `1'0` | 0 | low |
   | 声明 1（qc） | `1'1` | 1 | high |

   ⇒ **“low” = {声明 0} ∪ {未声明}**，且映射后二者不可区分。

## 2. 器件事实（补充资料，不影响上述结论）

Quartus 13.0（本机 `/mnt/d/QuartusII_13.0`）官方仿真原语 `quartus/eda/sim_lib/altera_primitives.v` 的 `dffeas`：

- `initial: if (power_up == "high") q_tmp_dly = 1'b1; else q_tmp_dly = 1'b0;`
  ⇒ 器件上电语义：非 `"high"`（含 `"DONT_CARE"`）一律 0。
- 其内部局部信号 `reset = devpor_in && devclrn_in && clrn_in && prn_in && ena_in;` 只用于 specify 时序检查与 `nosloadsclr`/`sloaddata` 门控；真正的行为由 `PRIM_GDFF_LOW/HIGH` 宏实现（清零输入 `!clrn_in`、置位输入 `!prn_in`）。

即：从“器件行为”层面，low（含未声明）上电 = 0 有官方依据；但“来源区分”（声明 vs 缺省）在映射网表中已丢失——**这是两个不同层面的问题**。

## 3. 现有等价检查如何处理“原始未定义初态 vs 映射后确定初态”

被执行的真实配方（EQY 策略文件 `work/strategies/<partition>/simple/run.ys`，本批次 `03_重跑受影响证明/run01` 各链一致）：

```
verilog_defaults -add -D CHECK_OUTPUTS
read_verilog -sv partitions/<p>.sv ; read_rtlil partitions/<p>.il
hierarchy -top miter; proc; chformal -cover -remove
async2sync
formalff -clk2ff -ff2anyinit gate.<p>
setundef -anyseq gate.<p>
flatten -wb; dffunmap; opt_expr -keepdc -undriven; opt_clean
sat -tempinduct -set-init-undef -set-def-formal -set-def-inputs -maxsteps 5 -set-assumes -prove-asserts -show-public -dump_vcd trace.vcd miter
```

各机制与位置：

1) 金侧“未声明 ⇒ 不强制”：`sat -set-init-undef`
   - 选项原文（`passes/sat/sat.cc:1007-1008`）：*“set all initial states (not set using -set-init) to undef”*；
   - 实现（sat.cc:289-296、337-344）：显式 init 属性先以 *“Import set-constraint from init attribute …”* 进入约束（`big_lhs/big_rhs`），随后 `-set-init-undef` 把**其余**初始位约束为 x（自由）。
   ⇒ 有声明者按声明值固定，未声明者自由。
2) 比较断言的容忍结构：EQY 生成的分区 `.sv` 中 `miter_cmp_prop`（例：`run01/test1/c4a_rtl_opt_mapped/work/partitions/test1.q4.sv:43` 实例化；模块定义同文件 61-73 行）：

```
okay = okay && (in_gold[i] === 1'bx || in_gold[i] === in_gate[i]);
```

   ⇒ 金侧未定义位放行；金侧已定义位要求与 gate 完全一致（`===` 严格相等）。
3) 网表侧（gate）FF 初值：

- v1 模型 FF 无 `initial` ⇒ “未初始化位”，`formalff -clk2ff -ff2anyinit` 将其替换为 `$anyinit`（自由）。选项原文（`passes/sat/formalff.cc:510-515`）：*“Replace **uninitialized** bits of $ff cells with $anyinit cells.”*；`setundef -anyseq` 把其余未定驱动变任意序列。
- ⇒ 第 03 轮现状：声明与未声明来源在 gate 侧同样“自由”，与金侧“未定义放行 / 声明值固定”对应。

4) v2 变更后的实际语义：
   - v2 对 `power_up=="low"` 生成 `initial q_tmp=1'b0`（**已初始化位**）⇒ `-ff2anyinit` 不再替换（formalff 只动未初始化位）⇒ gate 侧被固定为 0；
   - 金侧未声明仍为 x/放行。
   ⇒ **关系**：v2 把“映射默认低电平”当作确定初值参与比较；这对“声明 0”来源是正确的，对“未声明”来源则是把“缺省/x”单方面确定化（金侧并未对应确定化）。
   - 观测影响（本批四例）：部分 FAIL 的形态由 step-0 边界移至更深步（如 base 1→2、跨 reset 边界处），**整体状态未变、无分区因 v2 变 PASS**（见 `03_重跑受影响证明/`）。
2) 由于 ff_map 已移除 init 属性，**映射后网表中无法区分 low 的两类来源**；若需区分，必须使用映射前信息（coarse 阶段 init 属性或 RTL 源码）。

## 4. 结论分级

- 已证实：
  a) “low” = {声明 0} ∪ {未声明}，缺省 x→low；映射后 init 属性被移除（源码 + 真实设计 + 控制实验三重证据）。
  b) 现有检查的对应关系：金侧“声明=固定、未声明=放行”；gate 侧 v1“自由”、v2“固定为映射值（含未声明来源）”。
- 合理怀疑：
  a) 把未声明来源固定为 0 会不必要地改变证明难度/形态（本批未见状态变化，但已见 CEX 深度移动）。
- 未证明：
  a) 若改用“仅固定声明来源”的口径，四例中的 UNKNOWN 是否变化（本轮按要求不重跑）。
  b) coarse↔mapped 寄存器对应的系统性规则（名称基本保留，但需专门核验后才能作为实现依据）。
