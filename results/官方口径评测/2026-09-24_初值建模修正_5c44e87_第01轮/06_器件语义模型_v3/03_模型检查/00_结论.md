## 1. 模型检查结果（金侧声明初值；真实检查）

| 检查 | 说明 | v2 模型 | v3 模型 |
| --- | --- | --- | --- |
| chk_plain | 普通寄存器等价 | PASS | PASS |
| chk_ena | 时钟使能（ena=0 保持） | **FAIL_DETECTED**（缺使能 → 反例） | **PASS** |
| chk_clr | 异步清零（clrn 低清零，清零优先于使能/时钟路径） | **FAIL_DETECTED**（缺清零 → 反例） | **PASS** |
| init_d0_low | 声明一致（0 vs 0） | （v2 同 v3 语义）PASS | PASS |
| init_d1_high | 声明一致（1 vs 1） | — | PASS |

| init_nd_low | 金侧未声明 vs 门 0 | — | no model（**掩蔽**，见 §3） |

- 结论：v3 的**清零/使能**语义经最小对照验证为“修复后一致、修复前可检出”；初值“声明一致→通过、声明冲突→检出”双向成立。
- 掩蔽前记录：本目录 `掩蔽期记录/` 保存了旧版检查（金侧未声明）的原始日志——当时 chk_ena/chk_clr 也显示 PASS，那是基例被掩蔽的**假象**，非模型正确。

## 2. v3 实现范围（对应器件语义，见 `../02_model_v3/00_v3说明.md`）

- 清零：`clrn` 低 = 异步清零（Quartus `sim_lib/altera_primitives.v` 的 `negedge clrn => q+:0`；`fv_lib/verilog/dffeas.v` 的 `arst=~clrn|(clrn&aload&~asdata)`）；
- 使能：`ena=0` 保持（`fv_lib` 的 `dffep(q, clk, ena, …)`；本轮网表 test1 217/222、test3 全部、test4 1/10 的实例 `ena` 为信号驱动）；
- 初值：`power_up=="high"→1`、`"low"→0`（`sim_lib` 的 `initial: power_up=="high"?1:0`）；
- 优先级：清零 > 使能/时钟装载（`async2sync` 后为同步复位语义，与金侧同型）；
- 未支持条件（`prn` 有效、`sclr/sload/aload/asdata` 有效、`power_up∉{low,high}`）由 `precheck_supported_config.py` **明确阻断**（本轮 493 个实例全部落在支持集内）。

## 3. 掩蔽机理（本轮“初值检查”的关键发现）

**事实**：任何含“未声明初值的普通 FF”的设计，在当前协议（`-set-init-undef` + `-set-def-formal` 同时启用）下，其**基例问题整体不可满足**：

- `-set-init-undef`：未声明初值状态位 → Sx 约束（`sat.cc:337-344`；导入见 `sat.cc:357-359` 的 `signals_eq`，含 undef 标志比较）；
- `-set-def-formal`：对所有 FF 在 t1 假设初值已定义（`satgen.cc:1206-1221`）：`assume(NOT(any(undef_q)))`；
- 两者矛盾 ⇒ `solve(NOT(property))` 恒 UNSAT ⇒ **该设计的一切断言（包括真反例）都无法被证伪**（基例“平凡通过”）。

**决定性日志（本目录）**：

| 日志 | 条件 | 结果 |
| --- | --- | --- |
| `T1_ena2_no_defformal.log` | 去 `-set-def-formal`，设计含未声明 FF | model found（可证伪） |
| `T2_ena2_full_seq1.log` | 全 flags，同一设计 | no model（被掩蔽） |
| `T1b_ena_tol_v2_noDF.log` | 去掩蔽 + v2 + 真实 miter 容忍项 | model found（检出 v2 缺使能） |
| `T1c_ena_tol_v3_noDF.log` | 去掩蔽 + v3 | no model（v3 一致） |
| `C2_ena2_flags_seq5.log` | 无容忍项版本 + 全 flags | no model（掩蔽与容忍项无关） |

**范围**：`$anyinit` 不参与 Sx 赋值（`sat.cc:265-272` 的 `forced_def`），故第 03 轮中由 `-ff2anyinit` 释放的门侧 FF 不受掩蔽；掩蔽由**金侧未声明的普通 FF**触发。

## 4. 影响与建议（待批准，未实施）

- 影响：四例中“金侧含未声明初值寄存器”的分区，其历史基例部分为平凡通过（UNKNOWN 结果的成因之一），这些位从未被真实检查；全声明分区（如 test1.state/por6_out/inter0007_out）为真实检查。
- 建议选项（不涉及算法/网表）：
  - 选项一（保守）：保持现行协议，在口径文档中如实标注“含有未声明初值 FF 的分区基例被掩蔽（不检查）”；v3 重跑（04 目录）即按此协议进行；
  - 选项二（去掩蔽诊断）：在同一套输入上仅去掉 `-set-def-formal`（最小对照 T1b/T1c 已证明其可检出真实差异且 v3 通过），先对受影响分区做**受控对照重跑**，评估新增反例/UNKNOWN；
  - 选项三：另定“未声明初值如何参与检查”的正式口径（与初值方案 A/B 一并决策）。
- 工具怪癖（记录）：常数条件 `$check` 报 “No SAT model available”（金丝雀实验遗留日志），与本结论无关。
