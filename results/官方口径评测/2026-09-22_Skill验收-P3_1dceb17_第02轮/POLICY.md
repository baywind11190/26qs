# P3 插件版稳定版本评测 v1

本入口用于稳定 Git 提交的完整本地插件评测。默认执行全部公开、回归、H2 正负例、规模、工具与测量自检，以及公开四例每侧五次性能测量。结果保存在 results/官方口径评测 的新轮次，拒绝覆盖。

## 来源与可比性

套件 h1h2-p3-v1 的输入从 2026-09-22_H1H2-P3_1dceb17_第01轮冻结。manifest.json 逐文件记录来源和 SHA-256。公共四题和 A/B/C/D/H1 来自当时冻结的提交树；H2 和规模来自本地自建用例。它们不是未见的官方隐藏题。

后续算法提交只决定 src/pmux_opt.cc；默认公共输入不会随算法提交悄悄更换。新算法类型要另补专项输入并升级套件版本。没有覆盖新类型时不能声称完整覆盖该算法。

流程 p3-plugin-v1 固定 Yosys 0.69 的已记录源码提交、实际工具二进制和数据文件指纹。P3 位于 fsm; opt 后、wreduce 前。流程一致性检查比较原生 synth_intel 与未加算法的拆分流程。变更工具、映射参数、统计或输入后，重新审核版本，不修改旧轮次解释新结果。

## 官方资料与本地实现

官方要求的本地来源见 Windows 执行说明 03 的 §3.2：项目赛题目录的答疑表 Sheet1 C21～C26 与补充说明.txt。Comb 逐例缩减率平均、DFF 不增加、CPU/内存开销及最终内置形态与旧 Total 主指标不同。目录名称不代表官方认可。

P3、每侧五次取中位数、固定 ABC、5ms RSS 采样都是本地实施选择。Total 仅保留诊断。此版本不计算臆造的官方分数或跨例内存开销阈值。

## 判定与边界

- EQY PASS 要求真实退出码 0、完成标记且无失败证据。超时、未证明、缺结果和工具错误分开记录。
- 分区反例是待复核证据，不直接等于真实算法不等价。原始 RTL 链同时保留 baseline 对照。
- c1/c2 不代替 RTL 到最终映射链。本地核心检查完成也不等于官方验收。
- 自建映射模型仅在支持的单元类型和每个 dffeas 的 aload 常量零条件下使用；不支持时记录 MODEL_UNSUPPORTED。
- H2 正例逐项跑参考语义；不再把未运行的 ctrl10 参考检查概括为 PASS。
- 测量器 CPU 使用 wait4，RSS 按进程组采样；共享页可能重复计算，短峰值可能遗漏，GNU time 包装开销也在观测中。
- 新轮次插件全新编译，不从历史结果复制 .so。算法、工具、历史成果不修改，不自动安装依赖、提交或推送。
- 原仓库已有未提交改动不阻止提取精确提交；不 checkout/reset/clean。只有工具或固定套件指纹变化等影响证据的情况才阻止执行。

## 调用与失败处理

validate.py plan <Git提交号> 只读检查；validate.py run <Git提交号> 默认完整执行，可用 --label 指定版本名。在 WSL Python 3 下调用。plan 不获取远程对象；对象缺失时查明目标，按当次授权 fetch，不擅自改用分支最新版本。

完整执行可能较久。查看本轮 stages.json 和各阶段日志，勿并行另跑性能实验。阶段失败保存证据；流程/工具自检失败停止依赖测试。独立阶段失败后能继续的阶段继续。修复后创建新轮次，不在历史输出中覆盖重跑。

退出码 0 仅表示本地核心检查完整；退出码 2 表示需复核。无论退出码，先看中文报告、未闭合链与缺证据项。最终内置 Yosys 验收始终为 NOT_RUN，留待下一阶段。
